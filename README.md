# Analytics-engine

FastAPI service that receives events from the mobile apps (Kotlin and Flutter) and the Spring backend, stores them in SQLite and computes the business metrics shown on the dashboard.

```
Mobile apps ── app_loading_time, screen_view, crash ──────────┐
                                                              ▼
Spring backend ── recommendation_shown, recommended_activity_selected,
                  friend_availability_used ─────────────▶  Analytics engine (FastAPI + SQLite)
                                                              │  /metrics/*
                                                              ▼
                                                  Streamlit dashboard (dashboard/)
```

## Repository layout

```text
analytics-engine/
├── main.py  config.py  db.py  filters.py  models.py  security.py  deps.py
├── routes/          one file per feature (events, summary, one per metric)
├── metrics/         pure metric functions, one per business question
├── dashboard/       Streamlit dashboard
├── docs/            event contract and integration guides
├── scripts/         seed_demo.py (demo data generator)
└── tests/
```

## Running the engine

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn main:app --reload --port 8000
python scripts/seed_demo.py --users 30                # demo data (with the server running)
python -m unittest discover -s tests -t .             # or: pytest
```

Interactive docs at `http://localhost:8000/docs`. The database is created automatically at `./data/analytics.db` (add `data/` to `.gitignore`).

### Environment variables

| Variable | Purpose | Default |
|---|---|---|
| `ANALYTICS_DB_PATH` | SQLite file | `data/analytics.db` |
| `ANALYTICS_INGEST_KEY` | Key (`X-API-Key`) to **write** events | empty = no protection (dev only) |
| `ANALYTICS_ADMIN_KEY` | Key to **read** metrics and delete events | empty = no protection (dev only) |
| `ANALYTICS_LOADING_THRESHOLD_MS` | Threshold for the loading time metric | `1000` |
| `ANALYTICS_FREE_TIME_BUCKETS` | Free time range limits in minutes | `30,60,120` |

## Dashboard

A Streamlit app that reads `/metrics/summary` and `/metrics/friend-availability`. It shows one section per business question, with metric cards, charts and tables, and a sidebar to set the engine URL, the admin key, the period, the app version filters and the number of days that define an active user.

```bash
pip install -r dashboard/requirements.txt
streamlit run dashboard/app.py
```

Optional environment variables: `ANALYTICS_URL` (default `http://localhost:8000`) and `ANALYTICS_ADMIN_KEY`. Run `python scripts/seed_demo.py` first to have data to look at.

## Events

All events share these fields:

| Field | Req. | Notes |
|---|---|---|
| `eventType` | yes | See the table below |
| `userId` | yes | UUID of the backend `User` (`user.id` in the login response) |
| `eventId` | no | UUID generated by the sender. If the sender retries, the duplicate is discarded |
| `sessionId` | no | App session id |
| `appVersion` | no | Backend events do not have one |
| `timestamp` | no | Client time (ISO 8601). If missing or more than 5 min in the future, the server time is used |

| `eventType` | Own fields | Emitted by |
|---|---|---|
| `app_loading_time` | `loadType` (`cold_start`/`warm_start`/`screen`), `screen` (required if `loadType=screen`), `durationMs` | Apps |
| `screen_view` | `screen` | Apps |
| `crash` | `screen`, `component?`, `exceptionType?` | Apps (sent on the next launch) |
| `recommendation_shown` | `recommendationId` (one per load), `freeTimeMinutes?` | Backend |
| `recommended_activity_selected` | `activityId`, `category`, `freeTimeMinutes?`, `recommendationId?`. Emitted when the user **joins** a recommended activity | Backend |
| `friend_availability_used` | `action` (`viewed`/`plan_created`/`plan_joined`, default `viewed`), `activityId?` | Backend (when `/api/friends/gaps` is called) |

The full contract, with examples and sender rules, is in [`docs/analytics-contract.md`](docs/analytics-contract.md).

### Ingestion

| Method | Route | Auth | What it does |
|---|---|---|---|
| `POST` | `/events` | ingest | One event → `{ "accepted": 1, "duplicates": 0 }` |
| `POST` | `/events/batch` | ingest | `{ "events": [ … ] }`, up to 500, all or nothing |
| `DELETE` | `/events` | admin | No parameters deletes everything. `?appVersionBefore=1.0.0` deletes only old versions |

Response codes: `201` saved, `401` invalid key, `422` invalid event (the sender should discard it), `5xx` or no network (keep it queued and retry with backoff).

## Business questions and metrics

Each metric is an independent feature (see `routes/` and `metrics/`); its definition is in the docstring of the `metrics/` module and in `/docs`. All are `GET` routes under `/metrics`, require the admin key, accept the same filters and return rates from 0 to 1.

| # | Business question | Route | How it is computed |
|---|---|---|---|
| 1 | Is the average app loading time under 1 second? | `/metrics/loading-time` | Average, p50 and p95 of cold starts, plus `underThreshold`. Also accepts `loadType=screen` and `screen=` |
| 2 | Which screen or component has the highest crash rate? | `/metrics/crash-rate` | Crashes / screen views per screen, with a per-component breakdown. `minViews` pushes low-traffic screens to the end |
| 3 | What proportion of recommended activities do students select during their free time? | `/metrics/selection-rate` | Unique (user, activity) joins to a recommended activity / recommendation loads with free time. Also returns `loadSelectionRate` (loads with at least one join), which never exceeds 1 |
| 4 | Which recommended category is selected most for each free time duration? | `/metrics/category-by-free-time` | Winning category in `0-30`, `30-60`, `60-120` and `120+` minutes, with a tie flag. Ranges are configurable (`buckets=`) |
| 5 | What percentage of active users use Friend Availability? | `/metrics/friend-availability` | Users with a `friend_availability_used` event / active users in the last `activeDays` days (default 7). Also returns the rate of users who created or joined a plan |

Common filters:

| Filter | Meaning |
|---|---|
| `from`, `to` | ISO 8601 date range (`from` inclusive, `to` exclusive) |
| `appVersion` | Only that exact version |
| `minAppVersion` | Drops older versions. Events without a version (from the backend) are kept |

`GET /metrics/summary` bundles every installed metric in a single call, intended for the dashboard.

### Adding a new metric

1. `metrics/<name>.py`: pure function `(conn, filters, ...) -> dict`.
2. `routes/<name>.py`: `router = metrics_router()`, the endpoint and, optionally, `summary_key` + `summary(conn, filters)`.
3. `tests/test_<name>.py`.

No shared file needs editing: `main.py` and `/metrics/summary` discover the routes automatically.

## Integrating the backend and the apps

| Guide | Audience |
|---|---|
| [`docs/analytics-contract.md`](docs/analytics-contract.md) | Everyone: events, fields, endpoints, error handling |
| [`docs/backend-changes.md`](docs/backend-changes.md) | Spring backend: async publisher, free-time calculation, recommendation ids, Friend Availability hook |
| [`docs/client-changes.md`](docs/client-changes.md) | Kotlin and Flutter apps: event queue, startup time, screen views, crashes, passing recommendation ids |

Summary of the design:

- **Who sends what:** if the backend already handles the information, the backend emits the event; otherwise the app sends it straight to the engine. Apps send loading time, screen views and crashes. The backend sends recommendations shown, selections and Friend Availability usage.
- **Recommendations and selections:** the backend generates a `recommendationId` per recommendation load and computes the user's remaining free minutes from their schedule. Both are returned in the `X-Recommendation-Id` and `X-Free-Time-Minutes` response headers, so the response body does not change. The app sends them back on `join` (`?recommendationId=...&freeTimeMinutes=...`) and the backend emits `recommended_activity_selected`.
- **Never block the user:** the backend publisher uses a bounded queue and short timeouts and drops events if the engine is down. Apps keep a persistent queue and retry with backoff.
- **Retries are safe:** `eventId` makes ingestion idempotent.

### Integration status

The engine, the metrics, the tests for them and the dashboard are implemented here. The backend and app changes are specified in `docs/` but are not part of this repository.

## Known limitations

- **SQLite:** enough for this size. The schema is standard SQL; moving to Postgres only requires changing `db.py`.
- **The ingestion key inside an APK can be extracted.** It protects against noise, not against a determined attacker. If the app sends events directly and this matters, validate the backend JWT in this service.
- **`Category` is duplicated** (`config.CATEGORIES` and `models.Category`) and mirrors the backend enum. A test checks that they match each other, not the backend.
- **Friend Availability plans:** the backend has no concept of a plan yet, so only `viewed` is emitted and the plan rate stays at 0.
- **Kotlin vs Flutter:** events carry no `platform` field, so the two apps cannot be compared on the dashboard yet.
- **Screen names** in the contract are provisional and must be identical in both apps.
- **Startup time** is measured from process start on Kotlin and from `main()` on Flutter, so the two values are not directly comparable.
- **Test status:** the data and metrics logic has been run with `unittest`. The FastAPI/Pydantic layer and the dashboard have not been run in the environment where they were written.
